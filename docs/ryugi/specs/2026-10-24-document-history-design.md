# Document 历史：行内富内容差异

日期：2026-10-24

状态：已实现，待 UI 验收

规模：中等改动，覆盖历史投影、富内容 diff、文档布局和协作回归验证。

## 目的

Document 已把 Loro CRDT 历史保存在本地 `doc.loro`，浏览器可在本地读取或在电脑在线时经实时转发获得包含历史的 snapshot，但没有可浏览的入口。提供一个只读历史对比界面，让 your human partner 看清文档从选定时间点到当前版本改了什么，同时保留实时协作文档。历史二进制只保存在本地，云端只负责在线转发。

## 已确认

以下均来自本次对话中的明确选择：

| 决策           | 结果                                                           | 依据                       |

| 历史入口与布局 | 右侧历史栏，临时代替评论栏                                     | q1 → A                     |
| 时间线粒度     | 连续编辑合并成段，可以展开原始提交                             | q2 → A                     |

| 云端历史边界   | 历史二进制留在本地；云端只在线转发，本地或电脑在线时可查看历史 | 设计稿评论明确补充         |

以下标为“实现默认”的规则是本稿的建议，不冒充已经确认的选择。

## 使用流程

1. 文档顶部提供“历史记录”入口。本地与云端实时文档都能到达该入口，包括外层 Cloud Header 隐藏内部 TopBar 的情况。
2. 打开后右侧显示编辑时间线，评论栏暂时收起。默认选取最新完整编辑段之前的一个可用时间点；不足两个可比较版本时显示明确空状态。
3. 点击编辑段，使用该段最后一次提交对应的版本作为起点。展开后可以精确选择段内某次 Loro change 的末尾。
4. 正文区域显示“历史时间点 → 对比基准时间”的只读行内 diff。保留标题、段落、列表、表格、代码、链接与现有内容渲染；用底色和删除线表示删除，用底色及可见增添标记表示新增。
5. 提供“仅看变更”和“上一处 / 下一处”；显示当前位置及总变更处数。修改块算一处，不能把其 delete/insert 两半算两处。移动到第一处、最后一处时禁用相应按钮。
6. 退出对比或点击评论入口，回到原来的实时编辑器及评论栏。保留原编辑器实例、协作绑定和评论草稿；对比期间正文不能编辑，也不能向历史内容添加评论。

第一版只提供行内布局。第二轮原型里的“并排”按钮用于选方案，不是需实现的第二套产品视图。

## 对比基准与实时协作

**实现默认：进入历史时冻结一份独立的 Loro snapshot，时间线和对比终点都来自这一份副本。** 改选历史起点时终点不变。

- 原实时编辑器及 `LoroSync` 保持挂载、继续接收更新；对比副本不得连接 `transport.update`、自动保存或文件写回。
- 不得对实时 `LoroDoc` 调用 `checkout`，不得把 diff 装饰节点写回它，也不得卸载原编辑器再靠重载恢复。
- 新的实际内容变更到达时显示“有新内容，更新对比”。只在点击后重建基准及时间线，避免当前差异漂移；光标、评论和单独状态消息不算正文变更。
- 更新基准时保留选中版本的确切 frontiers，不能靠列表索引或显示时间重新定位。旧提交被 Loro 合并到更大的 change 中时，仍保留已选的操作边界。
- 若正在 agent 流式写入，显示“等待本轮编辑完成”并禁用更新基准；本轮稳定后提示可以更新。进入时若正在写入，保留加载提示和退出入口，等流式写入结束再获取完整基准。
- 本地页面可以继续读取本地历史；云端页面仅在本地电脑在线且实时转发连接可用时提供历史。云端断线后关闭历史对比、清理专用对比副本与投影结果，并禁用历史入口，提示“电脑离线，历史暂不可用”；原实时文档实例及协作绑定保持原有断线恢复行为。重连后重新获取历史及基准，不沿用旧的对比缓存。

## 历史投影与分组

在浏览器使用已有 snapshot，不增加历史写入接口，不改变现有持久化格式。

1. 在冻结副本上枚举 changes，按起始 Lamport、peer、counter 的稳定顺序构建因果有效的累计前缀；墙上时间只用于展示与编辑段的时间间隔判断，不用于判定因果先后。
2. 每个 change 的结束操作是 `{ peer, counter: counter + length - 1 }`。每个列表项保存累计前缀的版本向量或对应 frontiers，包含前缀中其他 peer 的修改。不能只把最后一个 peer 的结束操作当作所有人的全局版本。
3. **实现默认：相邻、同 peer、同编辑来源，且有效时间戳间隔在 0–60 秒内的 changes 合成一段。** 跨 peer、来源变化、未知来源、缺少时间或时间倒退均切段。该规则只合并展示，不删除原始记录。
4. 来源从已有 commit message 判断：`human` 为“浏览器编辑”，`agent:` 开头为“Agent 编辑”，`session ` 开头为“会话开始”，其余为“未标记编辑”。原始 message 可查看；不推测历史作者姓名，也不自动生成修改摘要。
5. 相同时间戳保留稳定顺序；缺失时间显示“时间未记录”，仍可选择。界面说明这些时间来自设备，列表表达因果前缀而非精确的全局墙钟快照。
6. 初次只渲染最近 50 段，点击“加载更早记录”再显示 50 段；显示展开后的原始 change 总数和明确的最早记录状态。仅为选中的起点重建内容，不为列表中的每项预先创建完整编辑器或版本副本。
7. 枚举与投影只在进入历史或手动刷新基准时执行。大日志分批工作，让加载状态与退出操作可响应；具体批处理方式由实现者选择，不提前引入 Worker。
8. shallow snapshot 只展示保留范围内可重建的记录，标注“更早历史未保留”。快照损坏、版本无法重建和缺少节点类型显示可重试错误，不转为一个看似成功的空文档。

## haklex 接入

已查看本机 haklex `0.54.2` 源码：

- `packages/rich-diff/src/RichDiff.tsx` 的现成 `RichDiff` 是双栏视图，实际参数为 `oldValue` / `newValue`；README 的 `before` / `after` 示例过时。
- `packages/rich-diff-core/src/compute-diff.ts` 导出 `computeDiff`、`diffModifiedNode`、`diffMergedNode`、`decorateSubtree`，具备结构与字符级差异能力。`DiffHunk.type` 实际是 `equal` / `insert` / `delete`。
- `rich-collab-loro` 的 `createLoroBinding` 可以把已有树投影到一个独立 Lexical editor；注册的节点必须与 Document 相同，生成序列化状态后立即 dispose。该 binding 存在双向写入能力，因此它只允许挂到独立 fork，不能绑定历史视图到实时文档。

实现时直接依赖与现有 haklex 包相同版本的 `@haklex/rich-diff-core`，复用它的对齐与装饰函数，用薄的一层行内展示组装各个变更块。不要为拿到 inline UI 引入带 Accept/Reject 的 agent 审稿流程，也不要重新实现字符 diff。

历史状态从独立副本 checkout 到累计 frontiers 得到，再用 `lexical.createEditor`、haklex 已导出的节点集合及 Document 的额外节点投影为 `SerializedEditorState`。接入实测发现 Loro 1.16.4 的 `forkAt` 不支持 shallow snapshot，因此统一使用 `fork` 后只对副本 checkout；实时文档不受影响。原始状态和 diff 装饰后的状态分开保存。

富内容展示复用 haklex 的只读 renderer 与本项目的 renderer 配置，补齐需要的匹配版本渲染包；优先用包的正式导出。不要全局迁移现有编辑器。接入前核对已发布包的真实导出；不能依赖邻仓源码中的未发布接口。

### 必须守住的 rich diff 行为

- 段落、列表和链接保留富文本样式；格式本身的变化也必须可见。纯加粗、链接目标、代码语言等属性改变不能被误判为“没有差异”。
- 表格在表格里展示内容变化，新增/删除行保留行结构；代码保持代码块排版。第三方引擎未覆盖的类型/属性使用明确标记的前后块展示，作为同一个修改块，不能静默丢失变化。
- 图片、图表、公式、图示等装饰节点复用现有安全 renderer，属性改变时显示对应前后内容；不承诺图片像素级 diff。
- 动态 HTML 历史对比仅展示 URL、参数和块属性差异，不自动运行历史 iframe；`pending` 显示当时保存的 intent，不启动编辑、完成或发布流程。
- 当前系统没有归档外部媒体/本地资源文件的各个版本。标注这一限制；若同 URL 下资源内容被覆盖，不伪装成已还原该资源的历史图像。
- 去掉 blockId 等内部标识及呈现缓存造成的假差异，保留影响内容或表现的属性差异。实现者明确映射这些已知字段，不能把所有非文本属性一概忽略。

若已发布 haklex 包缺少必需的能力，只修复有回归用例的具体缺口；涉及邻仓发布先报告该实际依赖，不能自行扩大成 haklex 全面重构。

## 布局与可达性

- 桌面右侧历史栏沿用现有 320px 评论栏位置，正文保持单栏阅读；历史与评论不同时挤占两条侧栏。
- 窄屏复用现有文档响应式布局及面板 primitive 选择版本；关闭版本面板后正文单栏显示同一份 rich diff。控制不能靠横向溢出才能到达，不新增并排阅读模式。
- 使用现有 Geist 字体、14px 正文与主题 token。新增/删除不只靠颜色区分，支持深浅主题、键盘、可见焦点和可访问名称；变更计数及错误状态可被读屏读到。
- Cloud Header 的历史入口需与本地一致可达，不能因 `TopBar` 在嵌入云端时返回 `null` 而丢失；具体复用现有外层 header 的方式由实现者决定。

## 云端与范围

历史二进制文件 `doc.loro` 只在本地持久化。云端只在本地电脑在线时转发实时请求与 snapshot，不把历史二进制写入云端存储、发布资源或备份副本。本地页面和在线 relay 页面复用 `DocumentView` 与实时取得的 CRDT snapshot；浏览器为显示对比而创建的内存副本不构成新的历史存储服务。

云端历史依赖在线转发，即便当前页面曾加载 snapshot，断线后也不提供缓存历史回看。仅有已发布 `SerializedEditorState` 的 `CloudDocument` 离线副本继续显示已发布正文，历史入口不可用并说明“电脑离线，历史暂不可用”。不扩大 publish payload 上传历史，也不新增云端离线历史缓存；重连后重新加载。

第一版不做恢复、回滚、接受/拒绝变更、版本命名、历史评论、自动摘要、任意两个历史版本配对或资源文件归档。也不修改 skills、CLI 工作流或云端历史存储。

## 预计触达范围

- `artifacts/src/viewer/document/`：独立的历史投影/分组 helper、时间线和行内 diff 展示；`DocumentPage`、`TopBar`、`DocumentLayout`、桌面及窄屏布局接线。共用节点/renderer 定义仅按实际调用需要抽取。
- Cloud Header 及 `CloudDocument` 的可用性说明；维持现有 local/relay transport 的读写边界。
- `artifacts/package.json` 与 lockfile：匹配版本的 haklex diff/只读渲染依赖；只列在构建依赖中，打包产物仍不声明 runtime dependencies。
- `artifacts/test/`：因果多 peer 历史、分组边界、富内容差异、不可写回及页面交互测试。
- 如实际修改 `artifacts/src/`，按仓库版本检查要求做版本 bump；发布与推送不属于本次设计确认。

## 验收

1. 在同一文档先后进行浏览器编辑、agent 文件编辑、重启服务，再从本地及在线 relay 看到一致的历史和内容差异。核对发布产物与云端持久化请求均未新增历史二进制；云端断线时历史入口和对比不可用，已有正文仍可读，重连后重新加载历史。
2. 多 peer 并发、相同/倒退/缺失时间戳、60 秒分组边界、初始化及 unknown message 都有行为测试。切到一个因果前缀不会丢失该前缀中其他 peer 的更改。
3. 真正接入 haklex，用段落、加粗/链接属性、列表、表格行及单元格、代码/语言、装饰节点的真实序列化数据验证差异；不能仅验证内部常量或 mock 引擎输出。
4. 打开、切换、关闭历史后，live frontiers、oplog、`transport.update` 次数不因浏览动作增加，`doc.xml`、comments 和持久化内容不被回看覆盖；新的远端内容仍正常进入原协作状态。
5. 快速切换版本时旧的异步结果不能覆盖新选择；基准冻结、新内容提示、手动更新、选中操作边界保留、空状态、错误重试及最早记录均可见。
6. 原型中已检查的 17 个交互分支只是设计证据；真实组件需重新验证。实测桌面、窄屏、深浅主题、键盘、所有变更导航和展开列表的末项。
7. 运行相关 Vitest、`pnpm typecheck`、`pnpm build` 与 `git diff --check`，把实际界面截图放回同一个 Artboard，供 your human partner 验收。

## 讨论产物

- 类型 `artboard`，id `document-history`，路径 `.ryugi/artifacts/artboard/document-history/`。`q1-a` 决定右侧栏，`q2-a` 决定编辑分组，`q3-a` 决定行内 rich diff；`flow` 是可点击设计原型，数据与差异为演示。
- 第一轮整篇旧版本预览仅作为历史讨论记录保留；最终需求由第二轮行内 rich diff 取代。
- 类型 `document`，id `document-history`，路径 `.ryugi/artifacts/document/document-history/doc.xml`。供阅读、编辑与评论本次完整设计，确认后与本文件同步。
