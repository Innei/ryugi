    <output file="output/stream-20000.txt"/>
  </claim>

  <claim id="ruling-streaming" judge="human" from="本机 dev server（pnpm dev，localhost:8787），feat/export @ a41c9e2" capturedAt="2026-11-28T15:42:31+08:00">
    <title>大批量导出改成了流式，每 500 条写一次，不在服务端生成完整文件</title>

  </claim>

  <claim id="ruling-quoting" judge="human" from="本机 dev server（pnpm dev，localhost:8787），feat/export @ a41c9e2" capturedAt="2026-11-28T15:42:31+08:00">

## 4. 写回设计文档

**Tool call 7(write)** `/Users/p/git/notes-app/.artideck/artifacts/document/export-design/doc.xml`
```xml
<doc>
  <h1>CSV 导出</h1>
  <h2>导出格式</h2>
  <p>每条笔记一行：id、title、body、updatedAt。UTF-8，逗号分隔。</p>
  <h2>大批量导出</h2>
  <p>超过 10000 条时，先在服务端生成完整文件，再一次性下载。</p>
  <p><ref verify="export"/> 实现与此不同：不生成完整文件，所有数量都流式下载，每 500 条写一次。</p>
  <h2>权限</h2>
  <p>只能导出自己的笔记。</p>
  <h2>实现结论</h2>
  <p><ref verify="export"/></p>
  <p>与设计不同的决定：</p>
  <ul>
    <li>大批量导出改成流式，每 500 条写一次，不在服务端生成完整文件。原因：一万条以上的完整文件在 Worker 上超出内存。如果用户需要断点续传下载，这条就错了。</li>
    <li>（设计留白，不是偏离）字段按 RFC 4180 加引号。原因：设计没说 title、body 里的逗号怎么处理。如果文件主要给不解析引号的工具或人眼直接看，这条就错了。</li>
  </ul>
  <p>踩过的坑：</p>
  <ul>
    <li>现象：流式导出的测试一直挂起。根因：数据库游标在最后一批之后没有关闭，连接池耗尽。解决：在 <code>finally</code> 里关游标，并给该测试加了 2 秒超时。</li>
  </ul>
</doc>
```
