  echo "## 3. neighbour: user B (3 notes) gets only own notes"
  curl -sS -b "$(cat .artideck/sdd/2026-11-10-export-design/session-user-b.cookie)" http://localhost:8787/api/export.csv

## 5. 写回设计文档

写入 `.artideck/artifacts/document/export-design/doc.xml`，全文如下：

```xml
<doc>
  <h1>CSV 导出</h1>
  <h2>导出格式</h2>
  <p>每条笔记一行：id、title、body、updatedAt。UTF-8，逗号分隔。</p>
  <h2>大批量导出</h2>
  <p>超过 10000 条时，先在服务端生成完整文件，再一次性下载。</p>
  <p><ref verify="export"/> 实现与此不同：改为流式导出，每 500 条写一次，服务端不生成完整文件。</p>
  <h2>权限</h2>
  <p>只能导出自己的笔记。</p>
  <h2>实现结论</h2>
  <p><ref verify="export"/></p>
  <p>与设计不同的决定：</p>
  <ul>
    <li>大批量导出改成流式，每 500 条写一次，不在服务端生成完整文件。原因：一万条以上的完整文件在 Worker 上超出内存。如果用户需要断点续传下载，这个决定就是错的。</li>
  </ul>
  <p>设计没有写明、实现时定下的点：</p>
  <ul>
    <li>字段按 RFC 4180 加引号。设计没说字段里的逗号怎么处理。如果使用方不认引号（账本里记的是只用 Excel 的人会看到引号），这个决定就是错的。</li>
  </ul>
  <p>踩到的坑：</p>
  <ul>
    <li>流式导出的测试一直挂起。根因：数据库游标在最后一批之后没有关闭，连接池被耗尽。绕法：在 finally 里关闭游标，并给测试加了 2 秒超时。</li>
  </ul>
</doc>
```
