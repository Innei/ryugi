### 我做的裁决（共 23 条，按时间顺序）

请先看带 ⚠ 的 6 条。第 3 和第 14 条偏离了已批准的规格；第 9、16、17 条影响用户数据，其中第 16、17 条的 ⚠ 是我写这条消息时重新评估的结果，账本里记的代价是"无"；第 23 条是未解决的测试失败。

1. Task 1：操作日志放在 `src/sync/oplog.ts`，而不是任务清单写的 `src/store`。原因是 store 不能引入网络层。代价：无。
2. Task 2：操作 id 用现有 ulid 工具生成的 ULID，不用 UUIDv7。原因是代码库只保留一种 id 方案。代价：无。
3. ⚠ Task 3：并发编辑按字段合并，每个字段最后写入者胜，**而不是规格 §4 写的按卡片合并**。原因是按卡片合并时，两人改同一张卡片的不同字段会丢掉其中一人的修改。代价：两人改同一字段时，仍有一人的修改会无提示地消失。
4. Task 4：IndexedDB 封装是手写的，约 60 行，没有引入 `idb` 依赖。代价：多一个文件要维护。
5. Task 5：同步 worker 是 module worker，打包器已支持。代价：很旧的 Safari 上同步无法启动。
6. Task 6：重试退避从 1 秒开始，上限 60 秒。规格未说明。代价：长时间断网后恢复较慢。
7. Task 7：队列测试使用 `fake-indexeddb`，它已是开发依赖。代价：无。
8. Task 8：重连横幅复用现有 Toast 组件。代价：无。
9. ⚠ Task 9：离线队列上限 5,000 条操作。超过后应用显示 "sync paused, reconnect to keep editing"，并停止接受编辑。规格没有提上限。代价：长时间离线后不再记录编辑。
10. Task 10：服务器确认每 200 毫秒批量发送一次。代价：确认延迟略增。
11. Task 11：冲突测试的夹具放在 `test/fixtures/sync`。代价：无。
12. Task 12：`applyRemote` 增加一个时钟参数，作为测试接缝。代价：无。
13. Task 13：看板版本向量存为 JSON 列，而不是单独的表，这样每个看板只读一次。代价：以后若要按它查询，需要一次迁移。
